# TARTIL 14.1 - Academy UX/UI redesign (learner program page, session, guides, privacy)

Date: 2026-11-03. Scope: Human-Formation Academy only (`#/academy...`) in `packages/web-vercel/index.html` and `packages/web/index.html` (identical except the `api-base` meta line; verified by diff and by e2e check 7h). The Quran reader, tafsir, tajweed, hifz, recitation and all Quran text were not touched. `docs/human-formation` and the generated JSON were not touched.

Status vocabulary: IMPLEMENTED (code written), TESTED (covered by `scripts/e2e_academy.mjs` section 7 or a validator, passing), PARTIAL, NOT DONE, NEEDS OWNER.

Owner feedback that triggered this: "the look does not suit me". Direction applied: Premium Arabic Learning Experience, Refined Islamic Heritage, Calm, Modern, Interactive. Existing project fonts only (IBM Plex Sans Arabic as `--ui`, Amiri as `--deco`, both already loaded by the project) and existing colour tokens; no new external font or library.

## 5. Not done, limits, decisions for the owner

1. Role detection uses what the client knows: institution memberships from `/me`. There is no age on the account, so a self-registered account with no membership can enter mentor mode by ticking the acknowledgement; that is the mechanism the brief asked for, but it is a declaration, not a verification. A user who holds a student membership in any institution is blocked even if he is also a teacher elsewhere (conservative). This is UI-level only; the academy JSON files remain public static files (audit F11), so the gate does not protect the data from a person who requests the JSON directly.
2. Guide and FAQ wording inside the JSON content (`guides/*.json`, `programs.json`, lesson key ideas) still contains phrases such as "لا يراه أحد إلا إن اخترتُ" and P07 "بإذنه" (audit F6). I did not edit content files. The displayed lesson privacy line and the parent view's privacy section were replaced by honest text, but FAQ answers and some guide sentences still come from the content and need an editor pass.
3. "أتعلم من المصدر" has no learner-facing step in the data, so it is not drawn (see 1.4). Needs a content decision if the owner wants it shown.
4. Progress is device-only. Server sync (directive item 16) is not implemented and nothing claims it; the existing `reflection_entries` server design is still not wired and needs the owner's decision on guardian consent and retention (audit section 4).
5. Publication-status lifecycle (directive item 13: draft, source review, scholarly review, approved, published) is not implemented. The visible state is still a single small "مسودة قيد المراجعة" chip on the home and program pages (the repeated banners were removed from the learner program page and lessons). Drafts are still reachable by any signed-in learner.
6. Scenario pages were only lightly touched (storage keys, finish handling); their layout was not redesigned.
7. Contrast was measured on opaque-background text; text over gradients/images was skipped by the checker. No screen-reader pass was done.
8. Existing progress saved by the previous build under unscoped keys appears only for the guest namespace; signed-in users start from zero on first load of this build.
